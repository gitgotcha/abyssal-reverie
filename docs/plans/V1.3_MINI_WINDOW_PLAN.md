## 0. 范围与已定决策

**做**（按依赖顺序）：① Rust 后台独立结算（ticker 落库）② 小窗窗口基建与共享状态 ③ 小窗 UI 与「完成任务并保存」④ 海洋伙伴基础状态机 ⑤ 音效/通知单源化。

**不做**：生命树/成长、种子收藏（第 5 项，另立方案）；伙伴进阶形象（水母/鲸鱼）与语音；点击穿透的高级场景；多树。

| # | 决策 | 状态 |
|---|---|---|
| D-1 | 后台结算：ticker 检测到期后**在 Rust 内完成结算并持久化**（写会话、确认片段、计时器转 done、发一次 `timer-settled` 事件携带结果）；前端改为订阅结果刷新 UI；`complete_timer` 保留并保持幂等（防双写以稳定 ID 去重） | 待确认 |
| D-2 | 小窗为**独立 WebviewWindow**（label `mini`），不用 owned/child 窗口——Windows owned window 会随主窗最小化而隐藏，与「主窗最小化后小窗可见」需求冲突；置顶用 `alwaysOnTop` | 待确认 |
| D-3 | 小窗默认 300×140 逻辑像素；支持折叠成计时条（约 300×44）；置顶开关、拖动、位置记忆（设备本地设置文件，**不入同步字段**）、临时隐藏；主窗关闭（隐藏到托盘）不影响小窗 | 待确认 |
| D-4 | 音效/通知只在结算点发一次（Rust 结算或主窗处理，向所有窗口广播的事件仅用于 UI 刷新，不重复触发副作用） | 待确认 |
| D-5 | 点击穿透默认关闭；如提供实验开关，必须有托盘/主窗可恢复入口，禁止把小窗锁成不可操作 | 待确认 |
| D-6 | 伙伴动画尊重 `reduceMotion` 设置与 `prefers-reduced-motion`；隐藏/折叠时停止动画（省 CPU/GPU） | 待确认 |

## 1. 阶段 A — 后台独立结算（Rust，前置硬依赖）

| ID | 任务 | 先写测试 | 涉及文件 |
|---|---|---|---|
| A1 | `settle_expired_timer(conn, session_id)`：结算逻辑从 `complete_timer` 抽出复用——写 session（eligible 判定）、确认片段、`timer_state` → done、返回结果；`complete_timer` 改为薄封装（幂等先行不变量保留） | `settle_writes_session_and_confirms_segments`、`settle_after_manual_complete_returns_existing`（双入口只有一条记录） | `repository.rs` |
| A2 | ticker（`lib.rs:171`）改为：检测到期 → `settle_expired_timer` → `emit("timer-settled", {session, timer, newlySettled})`；事件去重 latch 保留；结算失败（DB 忙/错误）退避重试并记录日志，不丢结算责任 | `ticker_settles_without_frontend`（不注册前端监听，断言 session 落库一次、timer 转 done）、`settle_retry_on_busy` | `lib.rs` |
| A3 | 前端 `timer-expired` 处理迁移：`handleExpire` 改为订阅 `timer-settled`（bootstrap 恢复路径保留 `complete_timer` 兜底）；自动休息、音效、通知由**结算事件**驱动且仅触发一次 | `auto_break_fires_once_per_settlement`、`frontend_free_still_updates_ui` | `App.tsx`、`tauriAppGateway.ts`、`FakeAppGateway.ts` |
| A4 | 快照广播：`start/pause/resume/switch/complete/finish` 后向**所有窗口** emit `timer-changed`（携带新快照）；主窗与小窗共同订阅，消除多窗轮询 | `all_windows_receive_snapshot_event` | `lib.rs`、`commands.rs` |

> 门禁：本阶段独立可发布价值 = 主窗无响应/隐藏时，会话照样只结算一次（方案 §2 P1 验收）。

## 5. 阶段 E — 发布收尾

1. 版本号、CHANGELOG、REGRESSION_REPORT、ACCEPTANCE_GUIDE。
2. 实机矩阵：100/150/200% DPI 不裁切；主窗最小化后小窗可见；关闭小窗计时不断；两窗并发暂停一次；拔外接屏位置回可见区；主窗无响应（devtools 断点阻塞）后台仍结算；24 小时长跑内存/CPU 基线。
3. NSIS + 便携构建；断网、干净 Windows、v1.2 库升级演练。

## 6. 验收案例（对应优化方案 §7/§11）

| 案例 | 预期 |
|---|---|
| 主窗最小化 | 小窗可见且倒计时正确 |
| 关闭小窗 | 后台计时继续，主窗重开无中断 |
| 两窗同时点暂停 | 只执行一次（revision 拒绝第二次） |
| 40 分钟轮次第 15 分钟在小窗完成任务 | 任务完成、15 分钟保存、主钟暂停剩余 25 分钟，非完整番茄；不补足 40 分钟 |
| 小窗保存失败 / 重复点击 / 到期竞争 | 可重试且不误标完成；成功只保存一份片段 |
| 撤销完成 | 任务恢复未完成，真实时间保留，主钟不自动继续 |
| 主窗无响应 | Rust 照样结算落库一次，重开后状态正确 |
| 休息中/未绑定任务点「完成任务并保存」 | 禁用并有说明 |
| 隐藏/折叠小窗 | 动画停止，CPU 回落 |
| 拔外接屏 / DPI 变化 | 小窗回到可见区域，无裁切 |

## 7. 风险

- Tauri 多窗口事件广播语义需实测（`emit` 全局 vs `emit_to`），A4 先做小型验证再铺开。
- 独立窗口与单实例插件、托盘隐藏逻辑的交互（关闭哪个窗口算退出）需在 B4 明确：**主窗与小窗都关闭且无运行中计时 → 退出；有运行中计时 → 全部隐藏到托盘**。
- 小窗渲染进程崩溃（WebView2 偶发）：Rust 计时不受影响，重开小窗从快照恢复；已知问题记录。
