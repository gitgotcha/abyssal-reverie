## 3. 跨版本不变量（任何版本不得破坏）

1. **30 秒资格规则只存在于 Rust**；React 仅渲染 `statistics_eligible` / `qualification_reason`。
2. **活动视图 = `statistics_eligible = 1`**；`abandoned` / `too_short` / 非专注记录只出现在显式 `scope=all` 查询与完整备份中。
3. **快照冻结**：会话记录任务标题、项目、类别、标签的**发生时名称快照**；改名不重写历史，统计按快照聚合。
4. **乐观并发**：计时命令一律携带 `expectedRevision`，冲突返回 `CONFLICT` 并触发前端全量 resync。
5. **幂等**：完成 / 结束 / 结算入口先查既有会话，重复请求返回既有结果且 `newlyRecorded=false`；奖励、确认片段按稳定 ID 去重。
6. **统计口径半开区间 `[from, to)`**，日界按本地日历日计算（v1.1.2 修复后为准）。
7. **离线可用**：除 v1.4/v1.5 的登录与同步模块外，核心任务、计时、统计在断网（且无服务端）时完整可用；同步失败不阻塞本地专注。
8. **单一权威计时**：所有窗口/入口共用后台计时服务快照；前端定时刷新仅用于展示。
9. **SQLite 单连接单写**：保留 `AppState.db` Mutex 模式；迁移在事务内、失败回滚保原文件。

## 4. 通用纪律

- TDD：每个任务先写失败测试再实现（Rust `cargo test`；前端 `vitest run`）。
- 每阶段门禁：`cargo test` + `pnpm verify`（tsc + vitest + vite build）+ `pnpm tauri build --no-bundle`；发布版另做 NSIS/便携构建与实机矩阵（干净 Windows、断网、中文/空格路径、旧数据升级、DPI 100/150/200%）。
- 分支：每版本从 `main` 拉 `feature/<version>-<主题>` 分支，每任务一提交；合入、打 tag、发 Release 另行门控。
- 文档：每版本更新 `docs/CHANGELOG.md`、`docs/REGRESSION_REPORT.md`、`docs/ACCEPTANCE_GUIDE.md`；行为语义变更（如重置、切换任务）必须在版本说明中向用户明示。
- Schema 迁移：只增不改语义；升级前自动副本；失败回滚保原库；**高版本库拒绝打开**（v1.1.2 落地后为硬门禁）。
