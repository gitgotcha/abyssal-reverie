## 0. 范围与已定决策

**做**：邮箱验证码登录、令牌存系统凭据库、本地游客档案 ↔ 账号档案绑定与迁移预览、同机账号切换隔离、**云备份**（版本化上传 / 列表 / 下载 / 恢复前预览）、账号设置与 README 定位更新。

**不做**：双向增量同步（v1.5）、第三方登录、邮箱密码登录、设备接力、在线权威计时、排行榜。

| # | 决策 | 状态 |
|---|---|---|
| D-1 | 产品定位改写为「离线优先 + 可选账号」；未登录功能完整（任务/计时/统计），登录页只讲「保存与换设备延续」的价值；README「无账号、不联网」表述随本版更新 | 待确认 |
| D-2 | **服务端选型为决策门**：候选 A = 托管 Auth + PostgreSQL（如 Supabase：Auth + 行级安全，快速验证；SQLite 离线合并不因其自动完成）；候选 B = 自建 API（可控、运维成本高）。先做候选 A 的可达性验证（用户所在地区域连通性）再锁定；区域与预算需用户确认，**不阻塞阶段 A** | 待确认 |
| D-3 | 第一版登录方式 = 邮箱验证码（6 位，10 分钟有效，限流）；令牌（access + refresh）存 **Windows 凭据管理器**（`keyring` crate），不落明文文件；退出登录撤销/清理 | 待确认 |
| D-4 | 账号隔离模型：延续 v1.2 `profiles`——游客是 `guest` 档案，登录后创建/绑定 `account` 档案；**同库双档案并存**，切换即切换数据空间，非仅换头像 | 待确认 |
| D-5 | 云备份定义为「手动 + 提示驱动的版本化备份」，**不是**多设备自动合并；同步语义在 v1.5 | 待确认 |
| D-6 | 客户端不得携带任何可绕过授权的管理密钥；服务端所有数据访问以认证身份限定用户 | 待确认 |

## 5. 门禁与实机验收

1. 阶段 A 独立门禁：`cargo test` + `pnpm verify` + 断网全功能可用。
2. 阶段 B/C 门禁：集成冒烟（真实后端 staging 或本地容器）+ 全量测试。
3. 实机验收矩阵：

| 案例 | 预期 |
|---|---|
| 未登录全流程 | 任务/计时/统计/归档完整可用，无网络请求报错 |
| 首次登录绑定 | 迁移预览数量正确；迁移后重试不重复导入；迁移前有自动备份 |
| 同机 A 登录 → 退出 → B 登录 | B 看不到 A 的任务；队列不以 B 身份上传 A 的记录（本版为手动备份，验证备份归属） |
| 断网时点备份 | 明确失败文案，本地不受影响；恢复联网后可手动重试 |
| 恢复备份 | 预览差异 → 确认 → 自动备份当前 → 导入成功；重复恢复幂等 |
| 令牌安全 | 凭据管理器中可见条目；文件系统无明文 token |
| 登录过期 | 横幅提示，本地功能继续 |

## 6. 风险

- D-2 选型未定是唯一外部依赖：阶段 A 完成后如仍无结论，本版可先发「本地档案管理 + 手动备份文件增强」，登录与云备份顺延，不空等。
- 邮件投递（验证码）在部分邮箱域易进垃圾箱：文案提示检查垃圾邮件；限流阈值保守。
- `keyring` 在 CI/无凭据服务环境的行为差异：测试用 feature 开关切内存实现。
