# 深海专注：管理体验与全局磨砂样式开发方案

> **For agentic workers:** 使用 superpowers:executing-plans 按批次执行；每批验证后再进入下一批。本文件是方案，不代表功能已实现或验收通过。

**Goal:** 保留原有深海主题，以管理内部侧栏组织任务、项目、标签，完善可选属性、日历、可靠保存与统一磨砂交互。

**Architecture:** 正式应用沿用 React + Tauri + Rust + SQLite；计时、预算及数据一致性由 Rust 保持权威。HTML 原型用于交互确认，正式应用复用其行为设计，不直接复制其内存数据逻辑。

**Tech Stack:** React 19、TypeScript、现有 CSS、Tauri 2、Rust、SQLite；拼音检索采用本地打包的 pinyin-pro。日期按本地年月日处理。

**Spec:** 本文第一至第四节为用户已确认规格，后续批次逐项实现。

## 一、范围与发布边界

- 原主题背景、配色、专注页及小窗整体结构保留；正式页面使用原视频与静态回退素材。
- 主侧栏仅有“管理”入口；管理内部左侧分类栏为任务、项目、标签，右侧展示相应内容。
- 统一磨砂涉及全系统面板、弹窗、提示与下拉层；业务重构仅限管理相关流程。
- 纳入时长展示、预算编辑、版本号来源修正，以及管理入口的专注动作语义。
- 不加入登录、云同步、植树、提醒通知、重复任务、多标签、项目分组新层级。
- “领域”沿用现有类别模型，不新增层级。
- 不执行全仓 cargo fmt，不混入无关重构。
- 不覆盖 release/v1.3.0 冻结产物；新版本号在打包阶段统一确定。新增包具有独立哈希与验收记录。
- 不操作真实库做故障注入。数据库升级与恢复先在副本验证。
- 当前 HTML 浏览器视觉验收因安全策略验证失败而未完成；DOM 测试不能替代实机验收。

## 二、确定的业务规则

### 2.1 任务与关联

默认创建只需标题。项目、标签、优先级、截止日期、备注均未设置；不得自动填“其他”标签或“中”优先级。在项目页面发起创建也不偷偷绑定；如需归入，表单明确展示选择，用户确认后保存。

一个任务至多属于一个项目、一个标签；当前版本不扩展多标签。未设置是空值，不是名为“未设置”的实体。列表不显示空属性占位，详情提供添加入口。

移除关联不删除实体。项目归档不删除任务、预算或历史。恢复任务及项目时保留归档前完成状态。归档项目不出现在新绑定候选中，但已有任务可以看到并解除旧关联。

项目完成需要没有未完成任务；项目内最后一个任务完成只更新进度，不自动完成项目。空项目可由用户主动完成。项目名称或标签改名不能拆分历史统计。

删除标签前显示影响数量。确认后清除任务的当前标签关联，不强制迁移至“其他”；历史发生时快照保留。既有内置标签的删除保护保留，但不承担新任务默认绑定。

撤销删除标签恢复标签实体；仅当受影响任务此后没有再次修改关联时恢复其旧关联，不能覆盖后续新选择。以关联修订号判定，不仅比较空值。

### 2.2 预算与计时

- 新任务默认 1 个番茄，其预算等于创建成功时已保存的单次专注分钟数 × 60。
- 创建面板实时显示当前换算；设置仍在保存时，提交等待其结果，失败则提示，不用未保存设置计算。
- 修改默认时长不改变旧任务预算，也不改变进行中或暂停中的轮次。
- 预算编辑显示旧预算、新预算和已投入量；主动确认后修改。已投入量不变，记录预算变更。
- 达到预算只显示“已达预计”，超出后如实显示超出量；任务完成必须由用户主动触发。
- 运行中切任务保持主钟剩余，投入分别归属；暂停中切任务不自动开始。
- “选择任务”只选择；空闲时“开始专注”选择并开始；已有轮次时明确写“切换到此任务”或“继续专注”，不隐式开新轮。
- 普通完成用于非活动任务；活动任务完成走现有原子“完成并保存”，暂停、封口并解绑。
- 撤销完成仅恢复任务状态，保留真实投入，主钟保持暂停。
- 30 秒资格、幂等结算、revision 守卫和历史片段精度规则全部继承现有 Rust 实现，不能由前端复制另一套。

### 2.3 查询与状态

任务查询标题、项目名、标签名与备注；项目查询名称与描述；标签查询名称。支持中文片段、大小写归一、全角半角归一、拼音及首字母。精确名称优先，其次前缀，再次包含匹配；同分使用稳定排序。

搜索与状态筛选同时生效，明确显示结果数量及条件。无结果时清除搜索/筛选；真实空集合提供新建入口；待办全部完成给出完成提示。

每个管理分类独立记住搜索、筛选、滚动、选中项。筛选排除选中项时收起详情，不能继续展示不相关内容。跨入口打开任务保留返回来源；返回项目/标签页恢复原位置。

新建后显示新条目；如它不符合当前筛选，明确提示并切到可展示视图，避免用户以为创建失败。

### 2.4 保存与日期

任务编辑使用显式“保存”提交一组修改，显示未保存/保存中/已保存/失败。选择器在新建或编辑表单中只修改草稿；详情快捷修改单字段立即保存并反馈，失败回退已保存值、保留可重试的新值。

切换任务或分类保留页面会话内草稿，返回提示恢复草稿；关闭应用有未保存内容时提示。提交期间禁用重复操作；中文输入法候选 Enter 不提交；多行备注 Enter 换行。

截止日期采用 YYYY-MM-DD，允许空值，不使用 UTC 日期解析造成偏移。仅到日期，不增添时分、通知或自动完成规则。今天不算逾期；本地日期跨天后刷新标记，已完成任务不持续显示逾期警告。

## 三、界面与日历规格

### 管理布局

主框架 → 管理 → 内部左侧任务/项目/标签分类栏 → 内容列表 → 按需详情。
宽屏并排列表与详情，窄屏详情为抽屉；不固定依赖整屏宽度，应依据实际内容容器宽度切换。

任务列表展示标题及已设置的属性，投入与预算使用一致格式。项目页展示领域、描述、任务数量与所属任务。标签页展示关联任务、排序与管理操作。核心动作可用键盘发现，不能只在悬停时出现。

### 日历选择器

点击“未设置”或已选日期打开统一深色磨砂弹层：
- 周一为首日；高亮今天和已选日期，不能仅靠颜色区分。
- 支持上/下月、点击年月切换月份和年份选择、返回今天。
- 今天、明天、一周后、清除日期四个快捷入口。
- 保留手动输入，严格校验真实日期，支持闰年及跨月。
- 打开时定位已选日期，否则定位今天；选择后关闭并返回触发器焦点。
- 方向键移动日、Enter 选择、Escape 关闭、Tab 正常移动；年份列表可滚动。
- 弹层随窗口边缘翻转和限高；通过 portal 避免被面板 overflow 裁切。
- 输入错误就地提示，不清空有效旧值；清除后回到“未设置”。

### 原主题与磨砂

以 src/features/shared/palette.ts 和 src/index.css 为基准：
- abyss #050709；graphite #0A1117；silver #B0C0C6；moonlight #E2EFEF。
- 主玻璃基准 rgba(8,13,18,0.24)、blur(18px)、原有细边框；最终透明度依原背景最亮帧校验。
- 菜单/弹窗采用更实的同色底层，正文不得依赖背景恰好较暗才能阅读。
- 统一正文、辅助文字、禁用文字、选中态、焦点态；普通文字对比目标至少 4.5:1。
- 使用系统中文字体栈；正文以 14–16px 为主，数字等宽；不重做品牌和背景。
- 避免嵌套 backdrop-filter；不支持模糊或降低动态效果时提供稳定实色回退。
- 菜单、对话框、提示共用层级规则；焦点框不被裁剪。

### 动效

分类切换仅内容短淡入 120–160ms，不移动整段文字、不缩放字体。按钮使用 120–150ms 色彩反馈。日历/弹窗淡入，关闭不拖延交互。禁止 transition: all、整页重复入场和列表搜索每字触发动画。系统 prefers-reduced-motion 与应用“降低动态效果”都关闭非必要动画。

建议公开前端类型：

```ts
type ManagementSection = 'tasks' | 'projects' | 'tags';
type TaskPriority = 'high' | 'med' | 'low';
type TaskMetadata = {
  projectId: string | null;
  tagId: string | null;
  priority: TaskPriority | null;
  deadline: string | null;
};
type NullablePatch<T> = { action: 'keep' } | { action: 'clear' } | { action: 'set'; value: T };
type RelationshipPatch = {
  taskId: string;
  expectedRevision: number;
  project: NullablePatch<string>;
  tag: NullablePatch<string>;
};
type DatePickerProps = {
  value: string | null;
  onChange(value: string | null): void;
};
```

原始字段映射需要同时兼容旧调用者；不能用 Option<T> 混淆“字段没传”和“主动清空”。新接口采用上述显式补丁，Rust 对应 serde tagged enum，在事务内校验实体存在、状态及 revision。

## 六、关键回归断言示例

```ts

expect(isValidLocalDate('2027-02-29')).toBe(false);
expect(addLocalDays('2026-12-28', 7)).toBe('2027-01-04');
// 预算：服务端创建结果为权威。
expect(created.targetSeconds).toBe(40 * 2 * 60);
expect(oldTask.targetSeconds).toBe(80 * 60);
expect(updatedProgress.confirmedSeconds).toBe(beforeProgress.confirmedSeconds);
```

上述函数新增于 localDate.ts：isValidLocalDate(value: string): boolean；
addLocalDays(value: string, days: number): string。预算断言在网关集成用例中用实际创建/查询返回值验证，不构造假成功响应。

撤销冲突必须覆盖：任务从标签 A 清空 → 用户主动设为 B → 撤销删除 A → A 实体恢复，任务仍为 B。即使用户设 B 后又主动清空，也不能恢复 A（修订号已变化）。

## 七、执行方式和完成标准

按 0 → 1 → 2 → 3 → 4 → 5 → 6 顺序推进，每批独立审查、验证、提交。范围内安全修正随批实施，不再逐项询问已确认的设计。

本方案的完成标准是：用户可以只输入标题创建任务，按需选择属性，通过统一日历设置截止日期，在管理内部三个分类流畅操作；任何保存、撤销或升级都不会悄悄改变真实历史。

视觉验收、正式数据升级与发布是不同门禁。尚未执行的检查如实保留，不以方案或原型代替完成记录。
